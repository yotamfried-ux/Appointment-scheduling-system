# ראיות — שלב 3 (Catalog + Availability + מנוע סלוטים)

סביבה: Supabase מקומי אמיתי. סטטוס: PASS / PARTIAL / NOT TESTED.

## מה נבנה
- מיגרציה `20261013000000_catalog_availability.sql`: `resources` (ברירת מחדל "העסק עצמו"), `services`, `availability_rules` (**אילוץ אי-חפיפה ב-DB** עם `btree_gist`), `availability_exceptions`; RLS מאולץ (חבר קורא, admin+ כותב); הרשאות עמודה (business_id/kind/is_default בלתי ניתנים לשינוי מהלקוח); טריגר שמונע הצבעה למשאב של דייר אחר.
- `create_business` כותב עסק+בעלים+resource+שירותים+שעות **בטרנזקציה אחת**; `replace_weekly_hours` אטומי (לוגיקה ב-`private` מאחורי בדיקת admin).
- מנוע סלוטים טהור (`modules/availability/slots.ts`) על רגעי UTC עם Clock ו-DST.
- UI בעלים: `/settings/services`, `/settings/hours` (שעות שבועיות, חריגים, **תצוגה מקדימה של 14 יום מחושבת מהכללים השמורים**), ניווט הגדרות, `HoursEditor` משותף ל-onboarding ולהגדרות.

## ממצאי צילומי מסך (תוקנו)
1. מובייל, רשימת שירותים: כפתורי פעולה דחקו את השם ("אימון א…") והמחיר נשבר ל-3 שורות → פריסה מוערמת, כפתורים מיושרים לתחילת השורה.
2. תצוגה מקדימה: "לא מוצע" צויר כבלוק שחור כבד (כמו תור תפוס) → טקסטורה מקווקוות; "תפוס" שמור לתורים אמיתיים (שלב 4).
3. נבדק ונפסל: מתג הפעלה בימים סגורים (תקין ב-RTL אחרי תיקון שלב 2).
