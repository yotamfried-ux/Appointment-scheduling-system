# יומן החלטות

> נרשם לפי הנחיית המשתמש: "אלך עם ההמלצות שלך. בגרסה הנוכחית נשתמש רק בתזכורות מייל עם Resend ולא עם WhatsApp."
> החלטה שמסומנת ⏳ ממתינה לפעולה או לאישור נקודתי לפני ביצוע.

| # | נושא | החלטה | מקור |
|---|---|---|---|
| D1 | ערוץ הודעות v1 | **אימייל בלבד דרך Resend.** ללא WhatsApp/SMS. ה-`NotificationChannel` port נשאר, בלי מימוש | הוראה מפורשת |
| D2 | Framework | Next.js (App Router) + TypeScript, full-stack | המלצה |
| D3 | Auth בעלי עסק | Supabase Auth + MFA (TOTP) | המלצה |
| D4 | חיוב מנויי SaaS | `BillingPort` עם adapters `manual` + `fake`; בחירת ספק נדחית עד בדיקת התאמה משפטית/מיסויית | המלצה |
| D5 | תשלום לקוחות קצה | מחוץ להיקף; מוכנות בסכמה + `PaymentPort` ללא מימוש | הוראה מקורית |
| D6 | צוות / נותני שירות | מוכנות בסכמה בלבד (`resource_id`), בלי UI ב-v1 | המלצה |
| D7 | שפות | עברית בלבד ב-v1, תשתית i18n מוכנה | המלצה |
| D8 | החזקת סלוט בזמן מילוי טופס | כן, 3–5 דקות, מוגבל לכמות ל-IP/טלפון | המלצה |
| D9 | תוקף אישור ידני | 24 שעות ברירת מחדל, ניתן להגדרה | המלצה |
| D10 | סיום ניסיון/חוב מנוי | מצב degraded: קריאה בלבד, הזמנות חדשות מושבתות; תורים קיימים ממשיכים לקבל שירות | המלצה |
| D11 | עמלת ביטול | נרשמת כ"חוב" בלבד, ללא גבייה | המלצה |
| D12 | סנכרון יומן | חד-כיווני (תורים ← Google) ב-v1 | המלצה |
| D13 | ייבוא חגים | לא ב-v1 (P2) | ברירת מחדל |
| D14 | גישת תמיכה לחשבונות | קריאה בלבד, מבוקרת ומתועדת; ללא התחזות | המלצה |
| D15 | Rate limiting | Vercel Firewall + מונים ב-Postgres; Redis רק אם יידרש | המלצה (מסמך 05) |
| D16 | CAPTCHA | Cloudflare Turnstile אדפטיבי | המלצה (מסמך 05) |
| D17 | MFA | מומלץ לבעלים, נדרש לפעולות רגישות, חובה לאדמינים | המלצה (מסמך 05) |
| D18 | פרויקט Supabase ייעודי | ⏳ אושר בעקרון; היצירה בפועל (עלות) תתבצע בתחילת שלב 0 לאחר הצגת העלות | המלצה |
| D19 | ענף `main` בריפו | ⏳ הריפו ריק ולכן אי אפשר לפתוח PR; נדרשת הרשאה לדחוף ל-`main` או שיצירתו על ידך | פתוח |
| D20 | חיווי חי בדשבורד (שלב 7) | **polling קל** (`/api/owner/version`, כל 10 שניות, רק בלשונית גלויה) במקום Supabase Realtime: Realtime דורש חשיפת ה-JWT לקוד הדפדפן, בניגוד להחלטת ה-cookies ה-httpOnly (מסמך 05). אפשר לעבור ל-Realtime עם טוקן צר ובעל תוקף קצר אם יידרש | סטייה מתוכננת, תועדה בתכנית שלב 7 |
| D21 | הצעות המתנה | סדרתיות (FIFO), הצעה חיה אחת לכל טווח זמן, תוקף 30 דק' (ניתן להגדרה), `auto_offer` ברירת מחדל פעיל; כל ההחלטות ב-SQL באותה טרנזקציה של הביטול | המלצה (שלב 7) |
| D22 | חיוב מנויים (שלב 9) | ליבה ניטרלית לספק + `BillingPort` (adapters `fake`, `manual` נשלחים; ספק אמיתי = adapter נוסף); מצב המנוי נקבע רק מ-webhook; **סיום ניסיון/חוב ⇒ degraded**: אין הזמנות חדשות, תורים קיימים ממשיכים, שום מחיקה | הבעלים: "תיצור את החיבור בצורת פלאג אין"; מדיניות degraded = המלצת docs/04 |

מותג/שם/דומיין (נדרש גם ל-SPF/DKIM/DMARC), מחירי חבילות, נתונים קיימים מ-Project 8, retention, סוג עסק "רפואה", pentest חיצוני, ייעוץ משפטי (מסמך 05, סעיף 14).
